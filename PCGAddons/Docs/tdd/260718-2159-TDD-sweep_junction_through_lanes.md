# Sweep — сквозные полосы перекрёстков, тесселяция и UV патча — Agent Execution Spec

Инкремент поверх выполненного `260718-2105-TDD-sweep_unified_node_junction_rework.md`. Три доработки патча: сквозная пара рукавов соединяется непрерывной полосой вместо двух конусов к центру (лечит «кинжал» отростка на T-стыке, перетяжку и щели), тесселяция патча минимизируется (ruled-лофты без промежуточных колец при отсутствии террейна), UV перерабатывается (V главной дороги течёт через перекрёсток, ветки и клинья — планарная развёртка вместо радиальной).

## Foundations (shared, used across units)

- Понятия из текущей реализации сохраняются: junction (`Center/Axis/E1/E2/Arms`), рукав (торцевой frame, `Right/Up`, углы `CornerCcw/Cw`, направления кромок, `VAtCut/VSign`, `WidthMul`), биссектрисный кламп, Безье-клинья, контракт «кольцо 0 лофта бит-в-бит равно торцу ленты».
- Новое понятие — сквозная пара: два рукава одного junction с углом между `Outward` не меньше `ThroughAngle` (константа `2.617994f` рад = 150°). При валентности 2 пара назначается всегда, независимо от угла. Из нескольких кандидатов выбирается пара с максимальным углом; при равенстве — с меньшими индексами рукавов (детерминизм). Не более одной пары на junction.
- Соответствие колонок профиля через полосу: если `dot(right_A_план, right_B_план) < 0` (кольца ориентированы встречно), колонка `j` кольца A соединяется с колонкой кольца B, у которой `x` ближе всего к `-x_j` (стабильный выбор меньшего индекса при равенстве); иначе — с ближайшей к `+x_j`. Асимметричный Custom-профиль при развороте даёт зеркальный скачок — допустимое ограничение, в документацию.

## Execution Plan

Units run in listed order.

### Unit 1 — Солвер: назначение сквозной пары

- Goal: junction знает свою сквозную пару, ветки знают точку примыкания.
- Touch:
  - `SweepNetworkJunction.cs` — добавить `public int ThroughA = -1; public int ThroughB = -1;` (индексы в `Arms`, `-1` — пары нет).
  - `SweepNetworkSolver.cs` — в `BuildNetwork` после сортировки рукавов: перебором всех пар вычислить `angle = acos(clamp(dot(OutwardA, OutwardB), -1, 1))`; кандидаты `angle >= 2.617994f`; валентность 2 — пара назначается безусловно; выбор — максимальный угол, при равенстве меньшие индексы.
- How: только перечисленное; setback-математика не меняется.
- Gate: bridge-задача `Task_SweepT_U1`: T-синтетика (сквозной сплайн 40 м + ветка, приходящая в его середину под 90°, топология руками: 1 junction, 1 кут на сквозном, привязка конца ветки): `PASS pair` — у junction `ThroughA/ThroughB` указывают на два рукава сквозного сплайна (их `Outward` противоположны с точностью до 5°). Синтетика Y 120°×3: `PASS nopair` — `ThroughA == -1`. Валентность 2 (один сплайн, один кут без ветки — искусственно удалить ветку из топологии): `PASS pair2` — пара назначена.
- On failure: ≤3 итерации, затем стоп и отчёт.

### Unit 2 — Билдер: сквозная полоса и ветки на её кромке

- Goal: патч с парой строит непрерывную полосу A→B, ветки лофтятся на её кромку; без пары — прежняя звезда.
- Touch: `SweepJunctionMeshBuilder.cs`.
- How:
  - Полоса: осевая — квадратичная Безье `P(t)` от `Frame.Position` рукава A к `Frame.Position` рукава B с контрольной точкой `Center`. Кольца полосы: количество `S = max(2, ceil(поворот тангенса Безье / maxAngleRad) + 1)` (поворот — угол между направлениями Безье при `t=0` и `t=1`); кольцо `t`: центр `P(t)`, `right(t) = normalize(lerp(right_A, rightB_matched, t))`, где `rightB_matched = dot(right_A_план, right_B_план) < 0 ? -right_B : right_B`; `up(t)` аналогично; ширины/вертикаль — колонки профиля с маппингом из Foundations, боковой множитель `lerp(WidthMul_A, WidthMul_B, t)`. Кольцо `t=0` — бит-в-бит торец ленты A, `t=1` — торец ленты B (позиции принудительно). Треугольники — квад-стрипы по `ProfileSegments`, виндинг как у ленты A.
  - Кромочные полилинии полосы: для каждой стороны (крайние колонки) — последовательность позиций по кольцам полосы; используются ветками и клиньями.
  - Ветка: осевой луч от `Frame.Position` ветки в направлении `-Outward` (к центру); точка примыкания `P_b` — ближайшее пересечение луча (2D в `E1/E2`) с кромочной полилинией полосы на стороне ветки; нет пересечения — с самой осевой Безье; вырожденное кольцо ветки — вертикальная колонка в `P_b` (боковой масштаб 0, вертикаль по профилю). Лофт ветки: линейный, 2 кольца без террейна (см. Unit 3), кламп по биссектрисам соседних зазоров сохраняется, дополнительно боковой кламп по кромке полосы (вершина не пересекает кромочную полилинию — 2D-пересечение бокового луча с полилинией, кламп `s`).
  - Клинья: между углом ветки и ближайшей точкой кромки полосы (и между соседними ветками) — та же Безье-фаска, что сейчас, с веером не к `Center`, а к `P_b` своей ветки.
  - Без пары (`ThroughA == -1`) — текущий код звезды без изменений.
- Gate: bridge-задача `Task_SweepT_U2`, T-синтетика Unit 1: `PASS strip` — существует цепочка колец полосы, кольцо 0 и последнее бит-в-бит равны торцам лент A/B (≤1e-4); `PASS nopinch` — минимальная ширина полосы (расстояние между кромками в каждом кольце) ≥ `0.9 * 2w`; `PASS branch` — ни одна вершина патча не совпадает с `Center` в плане ближе `0.1` (нет схлопа в центр); `PASS partition` — сетка 32×32: покрытие ≤ 1 треугольником (вне рёбер, допуск 1e-3); `PASS seams` — торцы всех трёх лент совпадают с патчем ≤1e-4. Y-синтетика: `PASS fallback` — патч строится, покрытие ≤ 1. X-синтетика 90°: `PASS xthrough` — назначена одна пара, вершины лофтов двух веток не пересекают кромки полосы (2D-проверка).
- On failure: ≤3 итерации, затем стоп и отчёт; не возвращать конусы к центру для сквозной пары.

### Unit 3 — Тесселяция: ruled-минимум

- Goal: без террейна патч и лофты не плотнее необходимого.
- Touch: `SweepJunctionMeshBuilder.cs`.
- How:
  - Лофт ветки и лофт звезды-fallback: `rings = 2` без террейна; с террейном — `max(2, ceil(dist/step)+1)` как сейчас.
  - Полоса: `S` по повороту Безье (Unit 2) без террейна; с террейном — `max(S, ceil(длина Безье/step)+1)` (длина — по 16-сегментной аппроксимации).
  - Клинья: сэмплы по повороту Безье-обода через `maxAngleRad`, минимум 2; с террейном — дополнительно не реже `step` по дуге.
- Gate: bridge-задача `Task_SweepT_U3`, T-синтетика без террейна, Ribbon: `PASS density` — суммарное число вершин патча ≤ `24 * vpr + 64` (полоса ≤ ceil(π/maxAngleRad)+2 колец даже в худшем случае, ветка 2 кольца, клинья по фаскам); повторный прогон с террейном 64×64: `PASS densityTerrain` — вершин больше, чем без террейна, вычисление успешно.
- On failure: ≤3 итерации, затем стоп и отчёт.

### Unit 4 — UV патча

- Goal: главная дорога течёт текстурой через перекрёсток, ветки и клинья без радиальных растяжек.
- Touch: `SweepJunctionMeshBuilder.cs`.
- How:
  - Полоса: `U = ProfileUs` (по колонкам маппинга), `V = (VAtCut_A + дуговая длина Безье от кольца A до кольца t) * uvScale` со знаком `VSign_A` — непрерывно с лентой A; на стыке с лентой B остаётся фазовый шов V — допустимо.
  - Ветка и её клинья, а также звезда-fallback целиком: планарная развёртка в фрейме junction: `U = dot(pos - Center, E1) * uvScale`, `V = dot(pos - Center, E2) * uvScale` (в террейн-режиме — по XZ-позиции до драпировки).
  - Кольцо 0 лофта ветки дублирует вершины торца ленты с планарным UV (позиции совпадают, UV разные — шов по линии примыкания, вершины не свариваются из-за разных UV — это ожидаемо).
- Gate: bridge-задача `Task_SweepT_U4`, T-синтетика: `PASS uvstrip` — V вдоль осевых вершин полосы монотонно и непрерывно с V торца ленты A (разрыв на кольце 0 ≤ 1e-3); `PASS uvplanar` — для веерных вершин ветки UV равен планарной формуле ≤ 1e-4.
- On failure: ≤3 итерации, затем стоп и отчёт.
