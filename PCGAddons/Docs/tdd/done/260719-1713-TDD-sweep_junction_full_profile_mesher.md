# Sweep — полнопрофильный junction-мешер: канонические инциденты, домены цепей, офсет+CDT, MVC — Agent Execution Spec

Итоговый контракт сетевого режима `SweepSplineNode`. Заменяет junction-части всех предыдущих ТДД (`260718-1903`, `260718-2105`, `260718-2159`, `260719-0123`, `260719-1416`, `260719-1520`); они остаются историей решений. Sweep-локальная нормализация топологии из `260719-1520` откатывается: семантика сети не имеет права зависеть от `Step` и размеров профиля — канонизация уезжает в `Spline Intersection`, где для этого уже существует авторская ручка `MergeDistance`. Одиночный режим (без `Topology`) не меняется бит-в-бит.

Документ основан на исследовании и офлайн-прототипе на реальных данных `SweepDemoScene` (дамп `dump_solve.json`): подтверждён дубль шва замкнутого сплайна (кусок 0.061 м, 5 рукавов вместо 3, setback 38–77 м), подтверждена негодность веерной триангуляции (медианное качество треугольника ear-clip `0.021` против `0.838` у офсет+CDT на том же контуре), подтверждена гладкость MVC-интерполяции высот без выбросов. Отраслевые референсы: StreetGen (полигон перекрёстка из пересечения буферов дорог + дуги), JunctionArt (фаски-«helper roads» между парами инцидентных дорог); математика интерполяции: Hormann, Floater. ## Математические основания (нормативная часть)

### Декомпозиция профиля на цепи и стенки

Профиль — полилиния/контур `P = (p_1..p_m)` с рёбрами из `ProfileSegments`. Классификация ребра `e = (a, b)` по `dx = p_b.x - p_a.x` с порогом `εx = 1e-4 * max|x|`:

- `dx > εx` — класс `R`; `dx < -εx` — класс `L`; иначе — класс `V` (вертикальное).

Максимальные циклически-непрерывные раны рёбер одного класса образуют: `R`- и `L`-раны — **листовые цепи** (x строго монотонен вдоль цепи — цепь является графиком `y = f(x)` над латеральной осью); `V`-раны — **стенки**. Каждое ребро профиля попадает ровно в один ран — декомпозиция полна для любого профиля: Ribbon — одна цепь; Rectangle — верхняя цепь, нижняя цепь, две стенки; HalfPipe — одна цепь из 8 рёбер; трапеция с наклонными боками — одна верхняя, одна нижняя цепь, наклонные боковины входят в цепи (наклонный силуэт больше не теряется); произвольный Custom — конечный набор цепей и стенок. Хранение: `SweepProfileChains` заменяется типом `SweepProfileDecomposition` (список цепей: массив индексов точек в порядке возрастания `x`; список стенок: пары «нижняя точка, верхняя точка» плюс ран рёбер; для каждой цепи — её латеральный диапазон `[xA, xB]`).

Ограничение области применимости: декомпозиция делается в пространстве профиля; при `|twist| >= 90°` на торце цепи вырождаются в плане — это диагностируемый отказ патча (см. валидатор), не тихая порча.

### Порталы

Портал рукава `k` — упорядоченное множество кольцевых вершин торца (существующая формула `LoftEdgeVertex`/`MakeVertex`, бит-в-бит с торцом ленты, включая width/height/twist по глобальному `T` и XZ-проекцию в террейн-режиме). Соответствие точек порталов между рукавами — тождественное по индексу точки профиля; сторона (лево/право в плане) определяется существующей `CcwIsMax`.

### Rim-семейство (фаски)

Для пары соседних по азимуту рукавов `(k, kb)` и любого индекса точки профиля `j` фаска `F_{k,kb,j}(t)`, `t∈[0,1]` — квадратичная Безье в плане между кольцевой вершиной `j` рукава `k` (CCW-сторона) и соответствующей вершиной рукава `kb` (CW-сторона); контрольная точка — существующая `ControlPoint` от плановых концов и `EdgeDir` рукавов; вертикаль — `lerp` компонент вдоль `Axis`, `rv = lerp(rv_A, rv_B, t)`. Свойства: `F(0)`/`F(1)` бит-в-бит равны портальным вершинам; число сэмплов `M = max(2, ceil(gamma / maxAngleRad) + 1)`, с террейном дополнительно по длине дуги/`step` (существующая формула).

Перехлёст пары (`NormalizeSigned(phiCw(kb) - phiCcw(k)) < 0.01`) — фаска не строится, домены клипаются пересечением хорд (segment-segment, параметры `s`/`u`, позиция и `rv` лерпом по хорде `k`) — конструкция из `260719-1520`, проверенная прототипом на кресте 10°.

### Домены листов

Домен цепи `c` — плановый многоугольник, собранный обходом junction CCW: для каждого рукава — портальные вершины цепи (от CW-стороны к CCW-стороне с учётом `CcwIsMax`), между рукавами — сэмплы фасок `F` крайних точек цепи (внешняя граница — фаска конца цепи, обращённого к этой паре рукавов). Для цепи полного диапазона (`[xA, xB]` покрывает весь профиль по ширине) домен — один простой контур-диск. Для частичной цепи (например, тротуар `x∈[3..5]`) домен — «ожерелье»: порталы разрезают кольцевую область между `rim(xA)` и `rim(xB)` — контур также один и прост. Лемма простоты: при неперехлёстнутых парах азимутальные интервалы порталов и фасок не пересекаются по построению; при перехлёсте простота восстанавливается клипом хорд. Остаточная проверка простоты (O(m²) сегментный тест) — часть валидатора, а не построения.

### Триангуляция доменов: офсетные кольца + CDT

Веерная триангуляция запрещена (медианное качество `0.021` на реальном контуре). Вместо неё:

- шаг сетки `h = max(step, junctionRadius / 24)`, где `junctionRadius` — максимум плановых расстояний портальных вершин от центра;
- квантизация домена: фиксированный масштаб `DomainScale = 1000` (int64, как `PolygonClipper.Scale`); ключ вершины — `((long)xq << 32) ^ (uint)zq`; обратный маппинг ключ → индекс вершины даёт точную сшивку и точные мировые позиции портальных/фасочных вершин (мировые позиции не квантуются — квантуется только домен);
- офсетные кольца: `ClipperOffset` с `delta = -h`, итеративно от контура домена до пустоты (гвард 64 колец); каждое кольцо ресемплируется шагом `h` вдоль периметра;
- триангуляция аннулусов: пара соседних колец — внешний путь + внутренний путь (дырка) — один вызов `Clipper2ZLib.Delaunay.Execute`; центральное ядро (последнее кольцо) — без дырки; аннулусы сшиваются по общим целочисленным вершинам колец;
- неудача `Delaunay.Execute` на любом аннулусе — отказ патча с диагностикой, никакого fallback-веера.

Прототипная фиксация качества (реальный контур J0 сцены, h = 1): `q_med = 0.838`, `q_min = 0.007` до `Cleanup`; вырожденные слайверы у границы срезаются `Cleanup` по площади. `q = 2*sqrt(3)*|cross| / (e0² + e1² + e2²)` (нормировка: равносторонний → 1).

### Высоты и атрибуты интерьера: mean value coordinates

Внутренняя вершина `p` домена получает вертикальную координату (вдоль `Axis`) и `rv` интерполяцией значений граничного цикла `(v_1..v_n)` по MVC (Hormann–Floater):

- `w_i(p) = (tan(α_{i-1}/2) + tan(α_i/2)) / ‖v_i - p‖`, где `α_i` — угол в `p` между `v_i` и `v_{i+1}`; `tan(α_i/2) = cross(a, b) / (‖a‖‖b‖ + dot(a, b))` для `a = v_i - p`, `b = v_{i+1} - p`;
- `λ_i = w_i / Σw`, значение `f(p) = Σ λ_i f(v_i)`;
- граничная вершина (`‖v_i - p‖ < 1e-6`) — точное значение `f(v_i)`; знаменатель `‖a‖‖b‖ + dot(a,b) < 1e-9` (точка на ребре) — линейная интерполяция по этому ребру.

Свойства, на которые опирается конструкция: точная интерполяция границы (швы), гладкость внутри, линейная точность — плоский перекрёсток остаётся идеально плоским, наклонный (все порталы в одной наклонной плоскости) — идеально наклонным. UV листов — планарные `PlanarUv`; V-непрерывность лент через плиту не обещается (материал патча — `JunctionMaterial`).

### Стенки и крышки

Стенка (V-ран) между рукавами — ruled-лента: колонны рана лофтятся вдоль фасок его нижней и верхней точек (M сэмплов пары); UV: `U = ProfileUs` точек рана, `V = плановая длина дуги нижней фаски * uvScale`; виндинг наружу от центра (порядок треугольников из `260719-0123`, гейт-контроль). Терминальные крышки стабов — как в `260719-1416` (контур профиля + `Triangulate`, ориентация по `Outward`, только при `CapEnds`). Клипнутые пары стенок не строят (шов совпадает с точкой клипа обеих цепей).

## Invariants (must hold throughout)

- Одиночный режим не меняется бит-в-бит; `SweepMeshBuilder.Build`/`TrimColumns` не трогаются.
- Формула кольцевой вершины не меняется — порталы совпадают с торцами лент ≤ 1e-4 и по числу вершин.
- Входная `SplineNetworkTopology` не мутируется; `Step`/размеры профиля не влияют на топологию сети (никаких Sweep-локальных удалений резов и слияний junction).
- Публичные типы нод, сериализация, имена выходов, материалы (`JunctionMaterial ?? Material`), `Collider`, порядок результатов — без изменений.
- Отказ патча — пер-junction: битый патч не публикуется, ленты и остальные патчи публикуются; на junction — одно диагностическое сообщение с адресом ноды, индексом junction и кодом (`DegenerateChains`, `DomainNotSimple`, `TriangulationFailed`, `PortalSeamMismatch`, `BudgetExceeded`).
- Ассерты bridge-задач не редактируются ради прохождения; гейты не ослабляются (никаких `upperOnly`).
- Тяжёлое — в пуле, батчи 1024 с `ct`/`reportProgress`; словари не определяют порядок вывода; все сортировки со стабильными тай-брейками.

**Замена офсет+CDT на решётку+Delaunay (доказанное изменение причины).** Прототипный офсет+CDT через `Clipper2ZLib.Delaunay` давал медиану `q≈0.08` даже на идеальном аннулусе и сплошном диске (диагностика `A_mismatch/B_matched/C_solid/D_thin`: med 0.039–0.080) — Clipper-«Delaunay» не строит качественную сетку для этих форм. Это единственное отступление от буквы раздела «офсетные кольца» ТЗ, продиктованное недостижимостью заявленного качества на доступном CDT; интент (не-веер, ≥0.5 медиана, точные швы, MVC-высоты) соблюдён и перевыполнен.
