# Принципы проектирования PCG4U

Как мы принимаем решения при проектировании фич, ТДД и кода. Каждое решение в ТДД сверяется с этим документом. Эталоны — старые, обкатанные ноды ядра; новые фичи копируют их паттерны. Копия живёт в обоих репозиториях (ProjectPCG и pcg4u-addons) — правишь один, синхронизируй второй.

---

## Продукт, а не прототип

- Мы делаем законченный, качественный продукт (Asset Store), а не MVP и не демки. Демо-сцены — витрина продукта, а не его замена.
- Упрощать фичу ради скорости реализации нельзя. Простота ищется в реализации, а не в отказе от сложных механик и богатых возможностей. Если фича кажется слишком дорогой — ищем более простую архитектуру той же фичи, а не урезаем её.
- Каждая фича доводится до конца: Undo/Redo на каждое действие пользователя, отмена вычисления, прогресс, детерминизм, осмысленное поведение пустых и невалидных входов, ничего лишнего в сценах и билде.
- Если фиче нужен механизм уровня ядра (инвалидация, кеш, пулы, trailing-резолв) — расширяем ядро, а не строим локальный обходной контур рядом с ним.
- Не переизобретаем существующее. Перед проектированием — изучение текущей реализации и доступного API: сериализуемые типы Unity и пакетов (`Spline`, `AnimationCurve`, `Gradient`, `TerrainData`) хранятся и используются напрямую, собственные форматы данных заводятся только когда готового типа нет или он несериализуем. Дублирующая реализация того, что уже есть в проекте или в Unity, — брак ТДД.

## Нода — центр всего

Пользователь живёт в графе. Всё авторское взаимодействие фичи — на ноде, а не во внешних инспекторах, окнах и компонентах-тулзах. Лестница владения данными — всегда выбирается самая верхняя применимая ступень:

- **Данные ноды.** Всё, что автор создаёт для этой ноды, — сериализуемые поля data-ноды (`[HideInNode]`, если в теле не рисуются). Правятся кнопками extras-рендерера (`CustomPcgNodeRenderer.DrawExtras`) и хендлами в SceneView; сцен-объекты и внешние ассеты не создаются. Эталон: `SplineNodeRenderer` (Start/Stop Edit — временный контейнер редактирования, результат возвращается в ноду), волюмы `PointsByVolumesNode` (список `PcgVolumeItem` в ноде + `PcgVolumeSceneEditor` с position/rotation/bounds-хендлами).
- **Ассет-хранилище контента.** Когда контент тяжёлый и разделяемый (текстура маски) — авто-создаваемый нодой ассет; в ассете только контент и его `ContentVersion`, вся конфигурация (world-размещение, режимы) — полями ноды. Эталон: `PaintMaskAsset` + `DensityByPaintMaskNode` (`Offset`/`Size` на ноде, кнопка Paint и параметры кисти — в рендерере ноды).
- **Внешний объект по природе.** Террейн, сплайн-контейнеры сцены, коллайдеры — то, что существует независимо от графа. Ссылка полем ноды или переменной блекборда; изменения ловятся контент-хешем (см. «Версии и инвалидация»).

Прочее:

- Параметры и входы — поля data-ноды: `[Input]`-поля подключаемы связями и перекрываемы значениями.
- Блекборд — параллельный путь, не основной: `PcgValue` с `ValueType`, равным типу поля ноды, — тогда порт кормится и прямым полем, и переменной (`TerrainObjectValue` → `TerrainData` + порт `Offset`, `SplinesValue` → `List<Spline>`).
- Editor-инструменты ноды обязаны работать при любом источнике значения: и из собственного поля `Data`, и из связи/пилюли (читать через `GetInputValue`, а не только `Data.<поле>`).

## Независимость нод

- Нода полноценна сама по себе: не требует внешнего компонента-тулзы, менеджера, порядка настройки или второй ноды-компаньона. Всё нужное — на входах и в полях.
- Ноды общаются только через порты. Скрытых глобальных состояний между нодами нет. В сценах от ноды ничего не оседает, кроме запечённого результата и временных объектов редактирования (`IPcgTemp`).
- Новые фичи не добавляют собственных вычислительных контуров: вычисление — только через `PcgComputeSystem`, материализация — только через `IInstanceMakerContainer`/`IInstanceMaker` (эталон: `GameObjectWeightsNodeExecutor`, `MeshInstanceMaker`).
- Мутация `Data` ноды из редакторского кода — строго по протоколу: `Undo.RegisterCompleteObjectUndo(host)` → правка → `EditorUtility.SetDirty(host)` → `executor.OnParametersChanged()`.

## Версии и инвалидация

- Правка данных ноды инвалидирует граф штатно (`OnParametersChanged` → `ParamVersion`) — точечно и только зависимое. Поэтому данные в ноде — предпочтительная ступень лестницы: им не нужны ни вотчеры, ни события.
- Для внешних объектов контент-хеш — единственный источник правды: `GetContentHash()` у `PcgValue`, компонентов и ассетов включает всё, что влияет на результат (контент, трансформ, активность). Эталоны: `TerrainObjectValue`/`TerrainDataValue` (подмешивают `PcgTerrainContentVersion`), `SplinesValue` (узлы + матрица контейнера).
- Executor обязан подмешивать хеши внешних ссылок — и из полей `Data`, и из связей — в `GetVersionSalt()`, иначе изменение объекта не меняет версию ноды. Эталон: `VariableNodeExecutor.GetVersionSalt`.
- Push-инвалидация открытых окон — по образцу `PcgTerrainWatcher` (событие Unity → инвалидация затронутых executor'ов → Repaint), общий обход графов — `PcgExternalContentInvalidator` (корень, вложенные `Inner`, инлайн-значения `SubGraphNode`). Собственные последовательности Invalidate/Resolve не городим.
- Финальную актуальность гарантирует trailing-резолв `PcgComputeSystem`: инвалидация во время вычисления приводит к однократному повтору с последней версией. На него полагаемся, свои очереди не строим.

## Параллелизм по умолчанию

Тяжёлое вычисление на главном потоке — дефект проектирования. Эталоны обхода однопоточного Unity API:

- `DensityByTerrainLayerNodeExecutor` — снапшот `terrain.GetAlphamaps(...)` на главном потоке, билинейный семпл в пуле потоков.
- `DensityByTextureNodeExecutor` — non-readable текстура читается через blit во временный `RenderTexture` + `ReadPixels`, дальше семпл по массиву в пуле.
- `ColliderSurfaceNode`/`ProjectToCollidersNode` — физика батчами `RaycastCommand.ScheduleBatch` (Jobs), чтение `RaycastHit.collider` только на главном потоке до/после батча.
- `PointsNearPointsOctreeNode` — пространственная структура + параллельный поиск (`UniTask.WhenAll`, батчи).
- `PointsByHeightNodeExecutor` — разбиение на батчи: `batchSize = PCG.MaxGeneratePoints; batches = max(4, ceil(total / batchSize))`, обработка в `UniTask.SwitchToThreadPool()`.

Правила:

- Unity API — только на главном потоке и только для снятия immutable-снапшота (пиксели, альфамапы, высоты, кадры сплайна, данные волюмов). Живой view на изменяемый объект в фон не передаётся.
- Слияние результатов батчей — детерминированное: у каждого батча свой индексированный слот, после `WhenAll` слоты сливаются по порядку индексов. Порядок элементов — часть контракта (Seed-воспроизводимость, Poisson, downstream-выборки). Старые ноды местами ещё мержат под `lock` в порядке завершения потоков — при доработке таких нод слияние переводится на индексированные слоты.
- Внутри батча каждые 1024 итерации — `ct.ThrowIfCancellationRequested()` и `PcgComputeSystem.ReportProgress(this)` (вотчдог считает тишину зависанием).
- Циклы, вынужденно живущие на главном потоке (Unity API), — через `OperationScope.Start(this)` + `await scope.Step(ct: ct)` (эталон: `ResampleSplinesNodeExecutor`).
- Выходы — из пула: `Results.Rent(capacity)`; пустой вход даёт `Rent(0)`, а не null — нода считается вычисленной с пустым результатом.

## Превью

- У каждого типа данных порта есть своя отрисовка превью — нода без превью не сдаётся. Эталоны: точки — `GizmosUtility.DrawPoints`/`DrawPointsByDensity` поверх `FastGizmos` (GPU-инстансный рендер с бэкендами Built-in/URP/HDRP, фрустум-куллинг, лимиты из `PCGSettings`); сплайны — `SplinesGizmoUtility.DrawGizmos` (кеш дискретизации `SplinesCache`); регионы — `RegionGizmoUtility.Draw`; графы — `GraphGizmoUtility`.
- Дорогая дискретизация для превью кешируется с инвалидацией по изменению источника (эталон: `SplinesCache` — `Spline.Changed`/undo/prefab).
- Ноды со сплитом выходов дают переключатели превью (`IShowResults`, `IPointsCount`), инстанс-ноды — `INodeInfo` со счётчиками.

## Editor-only и сборка

- Генерация живёт только в редакторе: executors, рендереры, вотчеры, инструменты — в editor-сборках; рантайм-сборки без editor-логики (правила dllify — см. `PROJECT_MAP.md`).
- Временные объекты редактирования в сцене реализуют `IPcgTemp` — `PcgBuildPreprocessor` вырезает их при сборке плеера. В билд попадает только запечённый результат.

## Чек-лист новой фичи

- Данные — на правильной ступени лестницы (нода → ассет-контент → внешний объект), с обоснованием в ТДД, если не на верхней.
- Data-нода с `PcgNodeInfo`/`PcgMemberInfo`; все типы по отдельным файлам.
- Executor: параллелизм по схеме выше, `GetVersionSalt` для внешних ссылок, превью, `IsEmpty`, счётчики.
- Extras-рендерер и/или сцен-хендлы, если есть авторская работа в сцене.
- `PcgValue`-тип для блекборда с `ValueType` = тип поля ноды (когда тип внешне-ссылочный).
- Инвалидация внешних объектов: контент-хеш + событие или вотчер + `PcgExternalContentInvalidator`.
- Undo на каждое действие пользователя; протокол мутации `Data`.
- `IPcgTemp` для временных сцен-объектов.
